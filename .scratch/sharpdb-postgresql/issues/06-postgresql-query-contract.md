# 06: PostgreSQL 查询契约全绿（含 `count(*)` 标签分歧）

**What to build:**

对 PostgreSQL 执行只读查询时，客户端拿到与另外两种引擎一致的结果：`{columns, rows, truncated?}` 信封、`@name` 参数绑定、行上限与截断标记、超时的固定文案、数据库错误的原样透传、以及错误消息不泄露凭据或本机路径。跑到这一票，**共享查询契约套件在 PostgreSQL 上全绿**——"新增一种数据库"的验收面到此完整。

其中有一条真实引擎分歧必须先处理：PostgreSQL 给未起别名的 `count(*)` 贴的列标签是 **`count`**，而 MySQL/SQLite 是 `count(*)`。按共享套件"断言必须两个引擎都能逐字满足"的既有规则，把该断言处理到两边都成立（起别名或移入引擎专属测试）。

**Blocked by:** 04, 05

**Status:** ready-for-agent

- [ ] 结果信封逐字正确：列名一次、每行是值的列表、只在真正被截断时出现截断标记。
- [ ] `@name` 占位由参数对象填入，键不带 `@`；整型按数字绑定、空值按 SQL NULL 绑定。
- [ ] 默认行上限与调用者指定的上限都生效；超过服务端上限被截到上限而不报错。
- [ ] 超时以固定文案报告，并指出可调的环境变量。
- [ ] 数据库自己报的错（表不存在、列不存在）原样到达，含调用者写的标识符。
- [ ] 占位符缺少参数是一个**可读的失败结果**，不是异常逃逸。
- [ ] 错误消息不含凭据、也不含本机路径（沿用既有 tripwire 断言）。
- [ ] `count(*)` 的列标签分歧处理完毕：改动后 **PostgreSQL、MySQL、SQLite 三份查询契约测试全绿**。
- [ ] 非 ASCII 文本以字符本身到达（沿用既有断言，PostgreSQL 上也通过）。
