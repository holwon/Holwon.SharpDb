# 06: 执行查询（SQLite）

**What to build:** AI 能执行一条只读 SQL 并拿到结果集。**此刻四个工具全部就位**，服务器功能完整。Guard 在这一票接入——用户查询是唯一需要过只读检查的入口。

**Blocked by:** 03, 05

**Status:** ready-for-agent

- [ ] `execute_query` 工具：必填 SQL + 可选参数对象 + 可选行数上限
- [ ] 参数用 `@name` 占位符；参数对象的键**不带** `@` 前缀
- [ ] 返回 `{columns, rows}` 信封（列名只出现一次）；行是数组的数组
- [ ] 类型表示：整数 / 小数 / 布尔 / 空值用**原生 JSON**，日期时间用 ISO 8601，二进制用 base64
- [ ] 到达行数上限时**截断并标记**（仅在截断时出现该标记），不报错
- [ ] 请求的行数被服务端**硬上限**静默裁剪，不报错
- [ ] 未显式传行数时用配置的默认值
- [ ] 超时用配置的秒数；超时时返回错误结果，消息含秒数与可操作建议
- [ ] **Guard 前置**：非只读语句在执行前被拒，拒绝文案清晰
- [ ] 数据库自身的错误**原样透传**（带前缀），AI 能看到表名 / 列名 / SQL 位置
- [ ] 错误消息里**隐去文件路径**
- [ ] 所有业务失败以 `IsError` 结果返回，**不抛异常**（协议层异常除外）
- [ ] MCP 端到端：**工具列表恰为 4 个**，四个工具的 annotations 全部正确，且一条拒绝路径确实返回 `IsError`

---

**验收说明**：只测外部行为——断言"这条查询返回什么"、`IsError` 与消息内容，不断言内省 SQL、也不断言抛了哪种异常（本来就不抛）。

**为何依赖 05**：本票含"四工具全注册 + annotations 正确"的全栈断言，四个工具齐了才断言得了。
