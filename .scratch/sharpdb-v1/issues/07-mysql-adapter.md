# 07: MySQL 适配器

**What to build:** 同一组四个工具在 MySQL 上全部工作。这一票**验证 ADR 0003 / 0004 的承诺**：新增一种数据库 = 新增一个 Provider 项目 + 装配处加一条分支，**Core 零改动**。若实现中发现必须改 Core，说明端口设计失败——那是本票要暴露的信号。

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] MySQL Provider 实现契约的全部五个成员，落在**同一个**深接口上
- [ ] 只读连接通过**会话级只读**达成（连接建立后立即设置）
- [ ] 内省从 `INFORMATION_SCHEMA` 取数，只看**当前库**（不跨 schema）
- [ ] 列出表：含表与视图、含注释、按名称排序
- [ ] 描述表：列（含注释与真正读到的自增标志）、主键、外键、索引；索引**排除主键**
- [ ] 列出数据库：返回该连接可见的库
- [ ] 执行查询：与 SQLite 同一套 `{columns, rows}` 形态、同一套行限 / 超时 / 错误透传 / 脱敏规则
- [ ] Core 侧**没有**任何 MySQL 专属分支——Core 只认识契约
- [ ] Provider 契约的**共享契约测试套件**跑在 MySQL 上，与 SQLite 跑的是同一份断言
- [ ] 集成测试用容器化 MySQL，镜像钉在 8.0；容器共用以避免每个测试起一个
- [ ] 无 Docker 时这些测试**跳过**而非失败

---

**验收说明**：断言与 SQLite 票相同的外部行为（"这个库里有哪些表 / 这张表长什么样 / 这条查询返回什么"），确保两个适配器对同一契约给出**语义一致**的应答。
