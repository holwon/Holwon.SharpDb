# 启动期配置错误与连接失败一律 fail-fast

SharpDb 在启动阶段解析配置并**主动探测一次数据库连接**。任何失败——缺 `SHARPDB__TYPE`、未知 type、缺/空连接串、连接串无法解析、凭据错误、主机不可达、目标库不存在——一律立即退出（非零退出码 + 单行 stderr 消息），而不是"照常启动、等工具调用时才报错"。

MCP server 由客户端以子进程方式拉起，用户几乎看不到它的运行时输出；一个"起来了但每次工具调用都失败"的 server 只会表现为莫名其妙的工具错误，排查成本远高于"根本没起来"。反之，进程立即退出会让客户端明确报告 server 启动失败，并带回 stderr 中的原因。把错误推到最容易被看见的位置，就是启动期。

**不单独做语法校验**：探测本身（开一条连接、随即关闭）就是最完整、最真实的校验——它同时覆盖语法与可达性。因此 `IDatabaseProvider` 不新增 `ValidateConnectionString` 之类的成员，启动探测复用已有的 `CreateReadOnlyConnectionAsync`，接口维持 ADR 0003 的 5 个成员。

**被否决的选项**：lazy（启动不连、首次工具调用才连），好处是数据库暂时不可用时 server 也能起来。否决理由：本工具是本地单用户使用，一个"起来了但每次调用都失败"的 server 带来的困惑大于收益，清晰的启动失败要好得多。

Consequences：启动依赖数据库可达；启动期 stderr 消息必须脱敏，绝不回显连接串本身。
